# Sisyphus 版本更新规划

> 最后更新：2026-05-29
> 规划范围：v0.1.0 → v1.0.0
> 版本格式：VA.B.C (beta n)，B/C/n ≤ 30

---

## 版本规划总览

| 阶段 | 版本范围 | 主题 | 预估总工作量 |
|------|----------|------|--------------|
| 第一阶段 | v0.1.0 - v0.3.0 | 项目骨架 + 核心数据模型 | 3周 |
| 第二阶段 | v0.4.0 - v0.7.0 | 核心算法实现 | 4周 |
| 第三阶段 | v0.8.0 - v0.11.0 | 核心功能模块 | 4周 |
| 第四阶段 | v0.12.0 - v0.16.0 | 进阶功能 | 5周 |
| 第五阶段 | v0.17.0 - v0.21.0 | 同步、搜索、成就 | 5周 |
| 第六阶段 | v0.22.0 - v0.26.0 | UI完善、深色模式、动画 | 5周 |
| 第七阶段 | v0.27.0 - v0.30.0 | 测试、优化、Bug修复 | 4周 |
| 正式发布 | v1.0.0 | 所有正式功能完成 | - |

**总预估工作量**：约30周（7-8个月）

### 发布节奏
- 每个版本完成后自动推送到 GitHub
- 每个版本保证可运行、可编译
- 每个版本包含完整的变更日志

### 版本号规则
- v0.1.0 - v0.30.0：开发版本
- v1.0.0：正式发布版本
- v1.0.0 (beta 1) - v1.0.0 (beta 30)：正式发布后的测试版本

### 质量保证
- 每个版本必须通过所有现有测试
- 每个版本必须无编译错误
- 每个版本必须无运行时崩溃
- 每个版本必须保持向后兼容

## 风险评估与应对

### 技术风险
| 风险 | 影响 | 应对策略 |
|------|------|----------|
| jieba-android 集成困难 | NLP 第二层延迟 | 准备纯 Kotlin 分词备选方案 |
| OneDrive API 限制 | 同步功能受限 | 实现本地备份作为降级方案 |
| 悬浮窗兼容性 | 番茄钟悬浮窗不可用 | 提供应用内计时器作为备选 |
| 性能问题 | 用户体验差 | 提前进行性能测试和优化 |

### 进度风险
| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 算法实现复杂 | 版本延期 | 预留缓冲时间，简化实现 |
| UI 设计迭代 | 版本延期 | 先实现基础 UI，后续迭代优化 |
| 第三方库问题 | 功能受限 | 选择成熟稳定的库，准备备选方案 |

本规划将 Sisyphus 项目分解为 31 个版本（v0.1.0 - v0.30.0 + v1.0.0），遵循"逻辑算法优先，UI和衍生功能后做"的策略，确保每个版本都可运行、可编译。

**关键里程碑**：
- v0.7.0：核心算法全部完成
- v0.11.0：核心功能模块全部完成

- v0.30.0：测试、优化、Bug修复全部完成
- v1.0.0：正式发布

1. 稳定性第一：不稳定的功能不做
