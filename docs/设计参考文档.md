## 一、项目概述

### 1.1 基本信息

- **项目名称**：Sisyphus
- **项目定位**：将原 LTS Program（HTML5+CSS3+vanilla JS PWA）重写为 Kotlin/Compose Multiplatform 原生应用
- **项目目录**：E:\Coding\Kotlin\Sisyphus
- **GitHub**：MokelungAAA 账户下的 Sisyphus 仓库
- **目标平台**：Android 优先（最低 Android 10 / API 29），后续扩展 Windows（Compose Multiplatform）

### 1.2 版本规则

- 格式：VA.B.C (beta n)，B/C/n ≤ 30
- 从 0.0.0 开始
- 所有官方功能完成后进入 1.0.0
- beta 仅在 1.0.0 之后开启
- 100 级 = 95% 得分率（不是 100%）

### 1.3 两大核心特性

1. **学习可视化**：智能经验值算法，自动拟合用户状态
2. **智能学习推荐**：根据用户录入信息和实际状态，智能推荐每日学习内容

### 1.4 完整功能清单

- 智能 XP 等级系统（自动拟合 + 固定等级映射）
- 智能学习推荐（背包 + 多约束算法）
- FSRS 间隔重复复习系统
- 自然语言数据录入（NLP 三层架构）
- 番茄钟计时器（自动录入 + 悬浮窗）
- 考试系统（NLP 检测模拟卷成绩）
- 阅读记录系统
- 学科 / 教材 / 知识点管理
- 统计面板与数据图表
- OneDrive 云同步
- 成就系统

### 1.5 开发策略

1. **逻辑/算法优先**：先实现核心算法，再做 UI 和衍生功能
2. **稳定性第一**：不稳定的功能不做
3. **避免空壳**：每个功能都要完整可用
4. **GitHub 版本控制**：每次小版本更新后自动推送

### 1.6 核心设计哲学

- **全自动执行 + 首页透明提醒 + 用户可调整**
- 系统足够智能可以全自动完成数据处理、推荐计算、进度追踪等操作，但保留用户随时调整的掌控感
- 首页设有提示区，引导用户完善信息（如补充番茄钟详情、确认推荐任务等），但不阻断用户操作
- 用户不需要停下来等系统处理，但永远知道系统在做什么、为什么这样做

### 1.7 应用性格

- **定位**：伙伴型，参考多邻国的陪伴风格
- **基调**：温暖鼓励，不施压
- **庆祝机制**：庆祝小胜利——连续天数达成、等级提升、考试进步等里程碑
- **提醒措辞**：温和引导，不用警告语气（如"你已经 X 天没学习了"改为"今天要不要继续前进？"）
- **吉祥物/角色**：暂不需要，后续可考虑

## 二、技术架构

### 2.1 技术栈

| 类别 | 技术选型 |
|------|----------|
| 语言 | Kotlin |
| UI 框架 | Jetpack Compose + Material 3 (Material You) |
| 依赖注入 | Koin（KMP 兼容） |
| 异步 | Kotlin Coroutines + StateFlow |
| 网络 | Retrofit + OkHttp |
| 导航 | Compose Navigation |
| 最低版本 | Android 10 (API 29) |

### 2.2 架构模式

- **Clean Architecture 三层**：Domain / Data / Presentation
- **模块化**：按功能模块划分（Feature-based）
- **设计原则**：高内聚、低耦合、可扩展

### 2.3 代码规范

#### 禁止项

- ❌ 禁止 WebView 直接加载原网页
- ❌ 禁止 !! 非空断言（用 ?.、?: 或提前判空）
- ❌ 禁止 GlobalScope（协程绑定生命周期）
- ❌ 禁止硬编码像素值（用 dp）
- ❌ 禁止 @Composable 内直接执行网络/数据库操作

#### 必须项

- ✅ UI 完全 Jetpack Compose + Material 3
- ✅ 状态提升：Composable 只显示，ViewModel 通过 StateFlow 提供数据
- ✅ 每个屏幕对应一个 @Composable + 一个 ViewModel
- ✅ 网络请求统一 Retrofit + OkHttp，sealed class Loading/Success/Error
- ✅ 颜色/字体/形状定义在 Theme.kt，遵循 Material 3 动态配色
- ✅ 导航用 Compose Navigation，绑定 ViewModel 生命周期
- ✅ 耗时操作用协程，viewModelScope.launch 调用

## 三、学习字段类型

### 3.1 字段定义

共 6 种学习字段类型：

| 字段类型 | 分类 | 说明 |
|----------|------|------|
| 课程 | 输入类 | 听课、上课等输入型学习 |
| 刷题 | 输出类 | 做题、练习等输出型学习 |
| 复习 | 输入类 | 回顾已学内容 |
| 笔记 | 输出类 | 整理笔记、做学科笔记 |
| 背诵 | 输入类 | 记忆、背诵类学习 |
| 默写 | 输出类 | 默写、默记等输出型学习 |

### 3.2 输入输出分类

- **输入类**：课程、复习、背诵
- **输出类**：刷题、笔记、默写

### 3.3 自动推断机制

- 字段类型根据用户的自然语言描述自动填入
- NLP 系统智能推断字段类型，避免用户手动选择
- 如果推断不准，用户可在确认面板中手动修正

### 3.4 进度关联

- 用户通过自然语言输入，系统自动匹配对应进度
- 示例：用户说"我有一个习题册刷到了 5.2"，系统根据进度推断下一节内容
- 用户可选择在进度界面勾选具体章节，但这是备选项，不强制

## 四、教辅/网课目录系统

### 4.1 问题背景

- 目录结构不能完全让用户自己建立（太麻烦）
- 内置常见教辅目录覆盖不够
- 需要同时支持教辅和网课两种类型

### 4.2 三种目录获取方式

#### 方式一：拍照 OCR 识别

- 用户对教辅目录进行拍照
- 系统自动采用文字识别识别对应目录
- 生成结构化的目录文件

#### 方式二：AI 搜索生成

- 用户自行填入 AI API Key
- 内置 AI 搜索功能，自动生成相关目录
- 适用于教辅和网课

#### 方式三：手动填写 + 智能识别

- 用户手动填写目录内容
- 系统智能识别章节分布
- 需要给用户一定的规范指导

### 4.3 教辅与网课并重

- 三种方式同时适用于教辅和网课
- 网课也需要统计进度
- 目录结构统一管理

### 4.4 数据结构

```
学科 → 教材 → 章 → 节 → 知识点（4 级灵活嵌套）
```

- 教辅目录 + 网课目录（两种类型都要支持）
- 阅读记录与学科记录分开（两个独立模块）

## 六、番茄钟系统

### 6.1 核心功能

- **自动录入**：计时结束后自动录入基础数据
- **数据补全**：首页弹出提醒，不跳出表单
- **悬浮窗**：环状番茄图标，实时显示进度

### 6.2 自动录入规则

- 仅包含以下字段（自动录入）：
  - 学科（必须提前选择）
  - 时长
  - 开始时间
  - 结束时间
- 其他所有字段都需要用户补充

### 6.3 数据补全流程

1. 用户开启番茄钟前必须选择学科
2. 计时结束后，系统自动录入基础数据
3. 在首页弹出提醒（不是表单弹窗）
4. 用户可随时补充其他字段

### 6.4 悬浮窗设计

#### 视觉形态

- 环状番茄图标
- 随时间增加红色部分（填充效果）
- 中间显示分钟数
- 暂停时：分钟改为暂停符号

#### 手势操作

| 手势 | 功能 | 说明 |
|------|------|------|
| 单击 | 开始/暂停 | 切换计时状态 |
| 双击 | 快速操作 | 仅在设置任务后可用 |
| 长按 1 秒 | 展开 | 显示更多选项 |
| 拖拽 | 移动 | 调整悬浮窗位置 |
| 边缘吸附 | 自动定位 | 靠近屏幕边缘自动吸附 |

#### 双击限制

- 如果用户没有提前设置在做什么任务，双击功能不可用
- 这是为了防止误操作

### 6.5 预设方案

- **经典方案**：25 分钟工作 / 5 分钟短休息 / 15 分钟长休息
- **自定义方案**：用户可自定义时间
- **休息规则**：每 4 个番茄钟一组，组间为长时间休息

### 6.6 后续扩展

- 模仿番茄 TODO 等成熟应用的功能
- 参考开源番茄钟实现
- 让用户看到成就感

## 七、XP 等级系统

### 7.1 等级映射（固定硬性指标）

| 等级 | 对应得分率 | 说明 |
|------|------------|------|
| 40 级 | 50% | 基础水平 |
| 50 级 | 60% | 进阶水平 |
| 60 级 | 70% | 中等水平 |
| 70 级 | 80% | 良好水平 |
| 80 级 | 85% | 优秀水平 |
| 90 级 | 90% | 卓越水平 |
| 100 级 | 95% | 顶尖水平（不是 100%） |

### 7.2 核心机制

- **映射关系固定**：等级与得分率的映射是硬性指标，永不调整
- **调整经验曲线**：如果用户达到对应等级但没有获得对应能力，调整经验值算法
- **不调整映射关系**：这是设计的核心原则

### 7.3 考试强制机制

- 每 10 级强制考试
- 必须有考试证明达到对应分数
- 小级别仅作为调整经验值算法的辅助数据

### 7.4 拟合数据来源（按重要性排序）

1. **考试得分率**（最重要）：考试是最重要的学习成果反映指标
2. **每日学习时长**：反映用户的学习投入
3. **FSRS 记忆参数**：反映用户的记忆效率
4. **任务完成量**：反映用户的学习产出
5. **完整高考模拟卷得分**：必须是完整高考题型的试卷

### 7.5 拟合算法要求

- 越精准越好
- 在缺少数据的情况下也能把经验归纳到相关地方
- 进行整体算法计算

## 八、智能推荐系统

### 8.1 算法核心

- **算法**：背包 + 4 约束
- **目标**：最大化学习效率
- **硬约束**：时间预算是硬约束，所有推荐任务总时长不得超过时间预算

### 8.2 四大约束条件

#### 约束一：时间预算

- 上限根据用户历史学习趋势计算
- 非简单平均，需要设计智能算法
- 根据用户过往任务消耗时间推算
- 根据完成系统推荐任务的数据调整

#### 约束二：输入输出比例

- **原则**：30% 输入 / 70% 输出
- **计算层面**：整体和单科都要计算
- **检测机制**：NLP 系统自动检测用户录入内容类型

#### 约束三：学科权重

- 根据用户日常学习时间分布推算
- 反映用户的偏好（前提是偏好合理）

#### 约束四：FSRS 复习优先级

- 遗忘曲线复习任务优先推荐

### 8.3 时间预算计算

- 根据用户过往每个任务所消耗的时间来分配
- 所有推荐的任务消耗时长加起来 = 这一天的学习时长趋势时间
- 需要根据用户的过往任务数据和完成系统推荐任务的数据
- 不能简单粗暴用平均，需要智能算法

### 8.4 学科权重调整

#### 手动调整

- 滑块（0-10）

#### 自动推算

- 根据用户日常学习时间推算
- 用户的学习时间反映偏好
- 高考选考科目：按分值比例或内置参数
- 高考非选科目：进一步降低权重

### 8.5 推荐优先级

- 时间预算是硬约束，所有推荐内容必须在预算内
- **第一步**：FSRS 复习任务优先填充时间预算
- **第二步**：完成复习任务后，剩余时间推荐新学习内容
- 推荐队列根据用户状态动态调整

### 8.6 输入输出平衡

- 短时间（1-2 天）不平衡：柔和提示
- 长时间不平衡：强烈提示
- 系统自动检测用户录入内容类型

### 8.7 推荐展示

- **今日推荐卡片**：列出推荐任务
- **时间预算模式**："你有 X 分钟，建议做 XXX"
- **两者结合**：同时展示推荐任务和时间预算

## 九、自然语言处理（NLP）系统

### 9.1 三层架构

| 层级 | 技术 | 覆盖率 | 延迟 | 说明 |
|------|------|--------|------|------|
| 第一层 | 正则表达式 | ~70% | 即时 | 离线处理，覆盖常见模式 |
| 第二层 | 设备端 NLP / jieba 分词 | ~20% | ~20ms | 离线处理，中文分词 |
| 第三层 | LLM API 回退 | ~10% | 较慢 | 在线处理，复杂场景 |

### 9.2 LLM API 优先级

1. GLM-4-Flash（免费优先）
2. DeepSeek-V3
3. Qwen-Turbo

### 9.3 用户体验

- **输入时**：实时高亮显示识别结果
- **提交时**：底部面板确认，用户可修正
- **两者结合**：实时反馈 + 最终确认

### 9.4 功能覆盖

- 学习字段类型自动推断
- 考试/模拟卷成绩检测
- 阅读记录自动识别

## 十二、复习系统

### 12.1 FSRS 间隔重复

- **评分标准**：4 档
  - Again = 0（完全忘记）
  - Hard = 1（勉强记住）
  - Good = 2（正常回忆）
  - Easy = 3（轻松回忆）

### 12.2 实现方式

- 纯函数 + 状态机
- 尽量不给系统运行带来负担

### 12.3 新用户过渡策略

1. **初始阶段**：使用 Anki 默认参数
2. **积累阶段**：前 50 张卡片使用 SM-2 算法
3. **切换阶段**：积累 50 张卡片数据后切换到 FSRS

### 12.4 遗忘曲线

- 延续 Anki 的合理机制
- 加入用户的学科时间比例权重
- 根据用户过往数据推测每天每科可用时间
- 根据用户偏好和选科确定推荐时间

## 二十六、数据流水线

### 26.1 番茄钟流水线

番茄钟结束 → 自动生成记录 → 立刻计算 XP（基于学科 + 时长）→ 更新连续天数 → 更新推荐队列

### 26.2 用户补充流水线

用户补充详情 → NLP 分析文本 → 重新计算 XP → 更新 FSRS 卡片状态 → 更新输入/输出分类

### 26.3 两次计算机制

- **即时计算**：番茄钟结束后立刻给予用户反馈（XP、连续天数等）
- **精细计算**：用户补充详情后，系统后台重新优化各项数据

## 二十七、大考模式

### 27.1 触发条件

用户设定考试日期后，系统自动进入大考模式。

### 27.2 自动调整

- 根据距离考试的时间线，逐步调整推荐策略
- 逐步停止新内容练习，切换成复习模式
- 首页提示："距离 XX 考试还有 XX 天，已进入冲刺复习模式"

### 27.3 得分达标策略

- 得分达标 → 优先攻克薄弱环节
- 未达标 → 继续巩固已学内容
