# Sisyphus 项目概要

## 一、项目基本信息

- **项目名称**：Sisyphus
- **项目定位**：将原 LTS Program（HTML5+CSS3+vanilla JS PWA）重写为 Kotlin/Compose Multiplatform 原生应用
- **项目目录**：E:\Coding\Kotlin\Sisyphus
- **GitHub**：MokelungAAA 账户下的 Sisyphus 仓库（待创建）
- **版本规则**：VA.B.C (beta n)，B/C/n ≤30，从 0.0.0 开始，所有官方功能完成后进入 1.0.0，beta 仅在 1.0.0 之后开启

## 二、核心功能

### 两大核心特性
1. **学习可视化**：智能经验值算法，自动拟合用户状态
2. **智能学习推荐**：根据用户录入信息和实际状态，智能推荐每日学习内容

### 完整功能清单
- 智能XP等级系统（自动拟合+固定等级映射）
- 智能学习推荐（背包+多约束算法）
- FSRS间隔重复复习系统
- 自然语言数据录入（NLP三层架构）
- 番茄钟计时器（自动录入+悬浮窗）
- 考试系统（NLP检测模拟卷成绩）
- 阅读记录系统
- 学科/教材/知识点管理
- 统计面板与数据图表
- OneDrive云同步
- 成就系统

## 三、技术架构

### 技术栈
- **语言**：Kotlin
- **UI框架**：Jetpack Compose + Material 3 (Material You)
- **依赖注入**：Koin（KMP兼容）
- **异步**：Kotlin Coroutines + StateFlow
- **网络**：Retrofit + OkHttp
- **导航**：Compose Navigation
- **最低版本**：Android 10 (API 29)
- **目标平台**：Android优先 → Windows（Compose Multiplatform）

### 架构模式
- **Clean Architecture三层**：Domain / Data / Presentation
- **模块化**：按功能模块划分（Feature-based）
- **设计原则**：高内聚、低耦合、可扩展

### 代码规范（禁止项）
- ❌ 禁止 WebView 直接加载原网页
- ❌ 禁止 !! 非空断言（用 ?.、?: 或提前判空）
- ❌ 禁止 GlobalScope（协程绑定生命周期）
- ❌ 禁止硬编码像素值（用 dp）
- ❌ 禁止 @Composable 内直接执行网络/数据库操作

### 代码规范（必须项）
- ✅ UI 完全 Jetpack Compose + Material 3
- ✅ 状态提升：Composable 只显示，ViewModel 通过 StateFlow 提供数据
- ✅ 每个屏幕对应一个 @Composable + 一个 ViewModel
- ✅ 网络请求统一 Retrofit + OkHttp，sealed class Loading/Success/Error
- ✅ 颜色/字体/形状定义在 Theme.kt，遵循 Material 3 动态配色
- ✅ 导航用 Compose Navigation，绑定 ViewModel 生命周期
- ✅ 耗时操作用协程，viewModelScope.launch 调用

## 四、算法设计

### 1. XP等级系统
- **等级映射（固定硬性指标）**：
  - 40级 = 50%得分率，50级 = 60%，60级 = 70%，70级 = 80%
  - 80级 = 85%，90级 = 90%，100级 = 95%（不是100%）
- **每10级强制考试**：必须有考试证明达到对应分数
- **小级别**：仅作为调整经验值算法的辅助数据
- **核心机制**：调整经验曲线，不调整映射关系
- **拟合数据来源**：考试得分率（最重要）、每日学习时长、FSRS记忆参数、任务完成量、完整高考模拟卷得分

### 2. FSRS间隔重复
- **评分标准**：4档（Again=0, Hard=1, Good=2, Easy=3）
- **实现方式**：纯函数+状态机
- **新用户过渡**：默认Anki参数，积累50张卡片数据后切换到FSRS
- **SM-2过渡**：前50张卡片使用SM-2算法

### 3. 智能推荐系统
- **算法**：背包+4约束
  - 时间预算（用户历史学习趋势为上限）
  - 30%输入/70%输出比例
  - 学科权重
  - FSRS复习优先级
- **上限计算**：多因素动态算法（非简单平均）
  - 根据用户过往任务消耗时间推算
  - 根据完成系统推荐任务的数据调整
- **输入输出分类**：NLP系统自动检测用户录入内容类型

### 4. 自然语言处理（NLP）
- **三层架构**：
  - 第一层：正则表达式（约70%，离线即时）
  - 第二层：设备端NLP/jieba分词（约20%，离线~20ms）
  - 第三层：LLM API回退（约10%）
- **LLM优先级**：GLM-4-Flash → DeepSeek-V3 → Qwen-Turbo（免费优先）
- **UX**：输入时实时高亮+提交时底部面板确认

### 5. 学科权重
- **手动**：滑块（0-10）
- **自动推算**：根据用户日常学习时间分布
- **高考选考科目**：按分值比例或内置参数
- **高考非选科目**：进一步降低权重

## 五、功能模块详细设计

### 番茄钟
- **自动录入**：仅包含学科（必须提前选择）、时长、开始/结束时间
- **数据补全**：计时结束后首页弹出提醒，不跳出表单
- **悬浮窗**：
  - 形态：环状番茄图标，随时间填充红色，中间显示分钟数
  - 暂停时：分钟改为暂停符号
  - 手势：单击（开始/暂停）、双击（仅在设置任务后可用）、长按1秒（展开）、拖拽（移动）、边缘吸附
- **预设方案**：经典（25/5/15）+ 可自定义，每4个一组长时间休息

### 学习字段类型
6种：课程、刷题、复习、笔记、背诵、默写
- 刷题、笔记、默写 = 输出类
- NLP自动推断字段类型

### 教材目录系统
三种方式并存：
1. 拍照OCR识别目录
2. 内置AI搜索生成（用户填入API）
3. 手动填写+系统智能识别章节分布

### 知识点系统
三层方案：
1. **内置基础库**：必须全面，涵盖各教材各小节（开箱可用）
2. **AI补充细节**：锦上添花
3. **自然积累**：用户使用过程中不断完善

### 数据结构
- 学科 → 教材 → 章 → 节 → 知识点（4级灵活嵌套）
- 教辅目录 + 网课目录（两种类型都要支持）
- 阅读记录与学科记录分开（两个独立模块）

### 考试系统
- NLP自动检测用户输入的考试/模拟卷成绩
- 仅完整高考题型模拟卷计入里程碑
- 高一高二阶段试卷不计入

### OneDrive同步
- **触发方式**：混合（自动+手动），设置页显示最后同步时间
- **冲突处理**：按字段合并，先自动合并再主页提示用户查看
- **参考**：Obsidian Remotely Save的认证机制

### 阅读记录
- 支持类型：读书、听书、笔记
- 通过自然语言直接记录
- 包含：类型、时长、书名
