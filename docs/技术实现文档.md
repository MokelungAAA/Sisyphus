## 四、FSRS 算法实现

### 4.1 算法概述

FSRS (Free Spaced Repetition Scheduler) 是间隔重复算法，用于优化记忆复习调度。Sisyphus采用4档评分标准，实现纯函数+状态机模式。

### 4.2 评分标准

| 评分 | 名称 | 含义 | 数值 |
|------|------|------|------|
| Again | 完全忘记 | 需要重新学习 | 0 |
| Hard | 勉强记住 | 回忆困难 | 1 |
| Good | 正常回忆 | 标准复习 | 2 |
| Easy | 轻松回忆 | 可延长间隔 | 3 |

### 4.3 FSRS 参数

```kotlin
data class FSRSParams(
    val w: FloatArray = floatArrayOf(
        0.4f, 0.6f, 2.4f, 5.8f, 4.93f, 0.94f, 0.86f, 0.01f,
        1.49f, 0.14f, 0.94f, 2.18f, 0.05f, 0.34f, 1.26f, 0.29f, 2.61f
    ),  // 17个可学习参数
    val requestRetention: Float = 0.9f,  // 目标记忆保持率
    val maximumInterval: Int = 36500     // 最大间隔天数(100年)
)
```

### 4.4 核心算法伪代码

#### 状态机转换

```
状态：NEW → LEARNING → REVIEW → RELEARNING
      ↑        ↓         ↓        ↓
      └────────┴─────────┴────────┘
               (遗忘时)
```

#### 纯函数：计算下次复习时间

```kotlin
fun nextReview(
    card: ReviewCard,
    rating: Rating,
    params: FSRSParams,
    now: Long
): ReviewCard {
    // 1. 计算稳定性变化
    val newStability = calculateStability(
        stability = card.stability,
        difficulty = card.difficulty,
        elapsedDays = card.elapsedDays,
        rating = rating,
        params = params
    )

    // 2. 计算难度变化
    val newDifficulty = calculateDifficulty(
        difficulty = card.difficulty,
        rating = rating,
        params = params
    )

    // 3. 计算下次复习间隔
    val interval = calculateInterval(
        stability = newStability,
        params = params
    )

    // 4. 返回新状态
    return card.copy(
        stability = newStability,
        difficulty = newDifficulty,
        elapsedDays = 0,
        scheduledDays = interval,
        reps = card.reps + 1,
        lapses = if (rating == Rating.AGAIN) card.lapses + 1 else card.lapses,
        state = determineState(card.state, rating),
        due = now + interval * 86400000L,
        lastReview = now
    )
}
```

#### 稳定性计算

```kotlin
fun calculateStability(
    stability: Float,
    difficulty: Float,
    elapsedDays: Int,
    rating: Rating,
    params: FSRSParams
): Float {
    val w = params.w

    // 遗忘曲线衰减
    val decay = (-elapsedDays / (stability * w[0])).exp()

    // 基于评分的稳定性增长因子
    val factor = when (rating) {
        Rating.AGAIN -> w[1]
        Rating.HARD -> w[2]
        Rating.GOOD -> w[3]
        Rating.EASY -> w[4]
    }

    // 难度调整
    val difficultyFactor = 1.0f - difficulty * w[5]

    return stability * (1 + factor * decay * difficultyFactor)
}
```

#### 难度计算

```kotlin
fun calculateDifficulty(
    difficulty: Float,
    rating: Rating,
    params: FSRSParams
): Float {
    val w = params.w
    val delta = when (rating) {
        Rating.AGAIN -> w[6]
        Rating.HARD -> w[7]
        Rating.GOOD -> 0f
        Rating.EASY -> -w[8]
    }
    return (difficulty + delta * (1 - difficulty)).coerceIn(0f, 1f)
}
```

#### 间隔计算

```kotlin
fun calculateInterval(
    stability: Float,
    params: FSRSParams
): Int {
    val interval = stability * (1 / params.requestRetention - 1)
    return interval.roundToInt().coerceIn(1, params.maximumInterval)
}
```

### 4.5 SM-2 过渡逻辑

新用户前50张卡片使用SM-2算法过渡：

```kotlin
fun sm2Algorithm(
    card: ReviewCard,
    quality: Int  // 0-5
): ReviewCard {
    val (ef, n, i) = Triple(card.easeFactor, card.reps, card.interval)

    val newEf = if (quality >= 3) {
        ef + (0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02))
    } else {
        max(1.3f, ef - 0.2f)
    }

    val newN = if (quality >= 3) n + 1 else 0
    val newI = when {
        newN == 0 -> 1
        newN == 1 -> 6
        newN == 2 -> (i * ef).roundToInt()
        else -> (i * newEf).roundToInt()
    }

    return card.copy(
        easeFactor = newEf,
        reps = newN,
        interval = newI,
        due = System.currentTimeMillis() + newI * 86400000L
    )
}
```

## 五、XP 算法

### 5.1 等级映射（固定硬性指标）

| 等级 | 目标得分率 | 说明 |
|------|-----------|------|
| 40级 | 50% | 基础门槛 |
| 50级 | 60% | 及格水平 |
| 60级 | 70% | 中等水平 |
| 70级 | 80% | 良好水平 |
| 80级 | 85% | 优秀水平 |
| 90级 | 90% | 顶尖水平 |
| 100级 | 95% | 极限水平（非100%） |

**核心原则**：等级映射固定不变，通过调整经验曲线适应用户。

### 5.2 考试强制机制

- 每10级强制要求考试验证
- 必须有考试证明达到对应得分率
- 未达标则暂停升级，等待补考

### 5.3 XP 计算核心算法

```kotlin
data class XPConfig(
    val baseXP: Float = 100f,           // 基础XP
    val levelMultiplier: Float = 1.5f,  // 等级增长系数
    val timeWeight: Float = 0.3f,       // 时长权重
    val qualityWeight: Float = 0.7f,    // 质量权重
    val inputOutputRatio: Float = 0.3f  // 输入占比（输出为0.7）
)

fun calculateXP(
    studyRecord: StudyRecord,
    userLevel: Int,
    config: XPConfig
): Float {
    // 1. 基础XP（基于等级曲线）
    val baseXP = config.baseXP * (1 + userLevel * config.levelMultiplier / 100)

    // 2. 时长因素（对数增长，避免无限刷时长）
    val timeFactor = ln(studyRecord.durationMinutes + 1f) / ln(60f)

    // 3. 类型质量系数
    val qualityFactor = when (studyRecord.inputType) {
        InputOutputType.INPUT -> 0.6f   // 输入类系数较低
        InputOutputType.OUTPUT -> 1.2f  // 输出类系数较高
    }

    // 4. 学科权重
    val subjectWeight = getSubjectWeight(studyRecord.subjectId)

    // 5. 最终XP
    return baseXP * timeFactor * qualityFactor * subjectWeight
}
```

### 5.4 经验曲线自动拟合

基于多个数据源拟合用户当前状态：

```kotlin
fun fitXPLevel(
    examScoreRate: Float,      // 考试得分率（最重要）
    dailyStudyMinutes: Float,  // 每日学习时长
    fsrsRetention: Float,      // FSRS记忆保持率
    taskCompletionRate: Float, // 任务完成率
    mockExamScore: Float?      // 完整模拟卷得分
): Float {
    // 加权综合评分
    val weights = floatArrayOf(0.4f, 0.15f, 0.15f, 0.15f, 0.15f)
    val scores = floatArrayOf(
        examScoreRate,
        normalizeStudyTime(dailyStudyMinutes),
        fsrsRetention,
        taskCompletionRate,
        mockExamScore ?: examScoreRate  // 无模拟卷则用考试得分率
    )

    return scores.zip(weights).sumOf { (score, weight) -> score * weight }
}
```

### 5.5 XP曲线调整策略

```kotlin
fun adjustXPCurve(
    currentLevel: Int,
    targetScoreRate: Float,
    actualScoreRate: Float
): XPConfig {
    val gap = targetScoreRate - actualScoreRate

    return when {
        gap > 0.1f -> XPConfig(levelMultiplier = 1.2f)  // 实际低于目标，降低升级速度
        gap < -0.1f -> XPConfig(levelMultiplier = 1.8f) // 实际高于目标，加快升级
        else -> XPConfig(levelMultiplier = 1.5f)        // 正常速度
    }
}
```

## 六、推荐算法

### 6.1 背包问题建模

将每日推荐视为多重约束背包问题：

```
最大化：用户收益（复习紧迫度 + 学科权重 + 输入输出平衡）

约束条件：
1. 总时间 ≤ 用户历史学习趋势时长（硬约束，背包容量）
2. 输入内容 ≤ 30%
3. 输出内容 ≤ 70%
4. 各学科权重平衡
```

### 6.1.1 推荐引擎优先级

**时间预算是硬约束**：用户每日可用学习时间构成背包容量，所有推荐任务必须在此容量内选择。

**填充顺序**：
1. **FSRS到期复习任务**：最高优先级，优先填充时间预算
2. **剩余时间分配给新学习内容**：在完成复习任务后，将剩余时间分配给新课程、练习等
3. **大考前自动切换**：当检测到距离考试日期较近时，逐步停止新练习，增加复习比例

**紧迫度计算**：
```kotlin
fun calculateUrgency(daysOverdue: Int): Float {
    return 1f / (1f + daysOverdue / 7f)
}
```

**推荐数量**：每次推荐3-5个任务，避免信息过载。

**算法详情**：详见 `算法理论支撑.md`

### 6.2 多因素动态上限计算

```kotlin
fun calculateDailyTimeBudget(
    weeklyStudyData: List<DailyStudyData>,
    dayOfWeek: DayOfWeek,
    taskHistory: List<TaskCompletionData>
): Int {
    // 1. 获取同类型日的历史数据（如所有周五）
    val sameDayData = weeklyStudyData.filter { it.dayOfWeek == dayOfWeek }

    // 2. 计算中位数（非简单平均，抗异常值）
    val medianMinutes = sameDayData.map { it.totalMinutes }.median()

    // 3. 任务完成率调整
    val completionRate = taskHistory
        .filter { it.isSystemRecommended }
        .map { it.completionRate }
        .average()

    // 4. 动态调整因子
    val adjustmentFactor = when {
        completionRate > 0.9f -> 1.2f  // 完成率高，可增加推荐
        completionRate > 0.7f -> 1.0f  // 正常
        completionRate > 0.5f -> 0.8f  // 完成率低，减少推荐
        else -> 0.6f                   // 完成率很低，大幅减少
    }

    return (medianMinutes * adjustmentFactor).roundToInt()
}
```

### 6.3 推荐项目生成

```kotlin
data class RecommendationItem(
    val type: RecommendationType,
    val subjectId: Long,
    val knowledgePointId: Long? = null,
    val estimatedMinutes: Int,
    val priority: Float,                  // 优先级分数
    val inputOutputType: InputOutputType
)

enum class RecommendationType {
    FSRS_REVIEW,        // FSRS到期复习
    WEAK_SUBJECT,       // 薄弱学科
    NEW_CONTENT,        // 新内容学习
    EXERCISE,           // 练习输出
    MOCK_EXAM           // 模拟考试
}

fun generateRecommendations(
    dailyBudget: Int,
    fsrsCards: List<ReviewCard>,
    subjectWeights: Map<Long, Float>,
    studyHistory: List<StudyRecord>
): List<RecommendationItem> {
    val recommendations = mutableListOf<RecommendationItem>()

    // 1. FSRS到期卡片（最高优先级）
    val dueCards = fsrsCards.filter { it.due <= System.currentTimeMillis() }
    recommendations.addAll(dueCards.map { card ->
        RecommendationItem(
            type = RecommendationType.FSRS_REVIEW,
            subjectId = getSubjectIdForCard(card),
            knowledgePointId = card.knowledgePointId,
            estimatedMinutes = estimateReviewTime(card),
            priority = calculateUrgency(card),
            inputOutputType = InputOutputType.INPUT
        )
    })

    // 2. 薄弱学科补充
    val weakSubjects = identifyWeakSubjects(studyHistory, subjectWeights)
    recommendations.addAll(weakSubjects)

    // 3. 输入输出平衡调整
    val inputTotal = recommendations
        .filter { it.inputOutputType == InputOutputType.INPUT }
        .sumOf { it.estimatedMinutes }
    val outputNeeded = (dailyBudget * 0.7f - (dailyBudget - inputTotal)).toInt()

    if (outputNeeded > 0) {
        recommendations.addAll(generateOutputRecommendations(outputNeeded))
    }

    // 4. 背包选择（贪心近似）
    return knapsackSelect(recommendations, dailyBudget)
}

fun knapsackSelect(
    items: List<RecommendationItem>,
    capacity: Int
): List<RecommendationItem> {
    // 按优先级/时间比排序
    val sorted = items.sortedByDescending { it.priority / it.estimatedMinutes }

    val selected = mutableListOf<RecommendationItem>()
    var remaining = capacity

    for (item in sorted) {
        if (item.estimatedMinutes <= remaining) {
            selected.add(item)
            remaining -= item.estimatedMinutes
        }
    }
    return selected
}
```

```kotlin
            text.contains("默写") -> StudyType.DICTATION
            text.contains("复习") -> StudyType.REVIEW
            text.contains("笔记") -> StudyType.NOTE
            else -> StudyType.COURSE
        }
    }
}
```

```kotlin
class LLMFallback(
    private val apiService: LLMApiService,
    private val tokenStore: TokenStore
) {
    // LLM优先级：免费额度优先
    private val providers = listOf(
        LLMProvider.GLM_4_FLASH,    // 智谱GLM，免费额度
        LLMProvider.DEEPSEEK_V3,    // DeepSeek
        LLMProvider.QWEN_TURBO      // 通义千问
    )

    suspend fun analyze(text: String): NLPResult {
        for (provider in providers) {
            try {
                val apiKey = tokenStore.getKey(provider)
                if (apiKey.isNullOrBlank()) continue

                val result = callLLM(provider, apiKey, text)
                if (result.confidence > 0.8f) {
                    return result
                }
            } catch (e: Exception) {
                Log.w("LLMFallback", "Provider $provider failed", e)
                continue
            }
        }

        // 所有LLM失败，返回基础解析
        return NLPResult(entities = emptyMap(), intent = StudyType.COURSE, confidence = 0.3f)
    }

    private suspend fun callLLM(
        provider: LLMProvider,
        apiKey: String,
        text: String
    ): NLPResult {
        val prompt = """
            分析以下学习记录文本，提取：
            1. 学科名称
            2. 教材/书籍名称
            3. 章节信息
            4. 学习类型（课程/刷题/复习/笔记/背诵/默写）
            5. 学习时长

            文本：$text

            返回JSON格式。
        """.trimIndent()

        val response = apiService.chat(provider.endpoint, apiKey, prompt)

    }
```

```kotlin
        super.onBind(intent)
        return binder
    }

    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        super.onStartCommand(intent, flags, startId)
        startForeground(NOTIFICATION_ID, createNotification())
        return START_STICKY
    }

    fun startTimer(subjectId: Long, durationMinutes: Int) {
        _state.value = PomodoroState(
            subjectId = subjectId,
            durationMinutes = durationMinutes,
            remainingSeconds = durationMinutes * 60,
            isRunning = true
        )

        timerJob = lifecycleScope.launch {
            while (_state.value.remainingSeconds > 0) {
                delay(1000)
                _state.update { it.copy(remainingSeconds = it.remainingSeconds - 1) }
                updateFloatingWindow()
                updateNotification()
            }
            // 计时完成
            onTimerComplete()
        }
    }

    fun pauseTimer() {
        timerJob?.cancel()
        _state.update { it.copy(isRunning = false) }
    }

    fun resumeTimer() {
        startTimer(_state.value.subjectId, _state.value.remainingSeconds / 60)
    }

    private suspend fun onTimerComplete() {
        // 1. 自动录入基础数据
        val session = PomodoroSession(
            subjectId = _state.value.subjectId,
            durationMinutes = _state.value.durationMinutes,
            actualMinutes = _state.value.durationMinutes,
            startTime = System.currentTimeMillis() - _state.value.durationMinutes * 60000,
            endTime = System.currentTimeMillis(),
            isCompleted = true
        )
        pomodoroRepository.saveSession(session)

        // 2. 发送通知提醒补全数据
        sendCompletionNotification()

        // 3. 更新悬浮窗为完成状态
        updateFloatingWindow(isCompleted = true)
    }
```

### 9.2 增量同步策略

```kotlin
class OneDriveSyncManager(
    private val oneDriveApi: OneDriveApi,
    private val localDb: AppDatabase,
    private val conflictResolver: ConflictResolver
) {
    // 同步元数据
    data class SyncMetadata(
        val lastSyncTimestamp: Long,
        val deviceId: String,
        val entityVersions: Map<String, Long>  // entityId -> version
    )

    suspend fun sync() {
        val lastSync = getLastSyncTimestamp()
        val now = System.currentTimeMillis()

        // 1. 获取本地变更（上次同步后修改的记录）
        val localChanges = getLocalChangesSince(lastSync)

        // 2. 获取远程变更
        val remoteChanges = getRemoteChangesSince(lastSync)

        // 3. 按实体ID合并
        val conflicts = mutableListOf<SyncConflict>()

        val allEntityIds = (localChanges.keys + remoteChanges.keys).distinct()

        for (entityId in allEntityIds) {
            val local = localChanges[entityId]
            val remote = remoteChanges[entityId]

            when {
                local != null && remote == null -> {
                    // 只有本地变更，上传
                    uploadEntity(entityId, local)
                }
                local == null && remote != null -> {
                    // 只有远程变更，下载
                    downloadEntity(entityId, remote)
                }
                local != null && remote != null -> {
                    // 都有变更，需要合并
                    val merged = conflictResolver.merge(entityId, local, remote)
                    if (merged.hasConflict) {
                        conflicts.add(merged.conflict!!)
                    }
                    saveMergedEntity(entityId, merged.mergedData)
                }
            }
        }

        // 4. 更新同步时间戳
        updateLastSyncTimestamp(now)

        // 5. 如有冲突，通知用户
        if (conflicts.isNotEmpty()) {
            notifyUser(conflicts)
        }
    }

    private fun getLocalChangesSince(timestamp: Long): Map<String, EntityData> {
        // 查询各表的updated_at > timestamp的记录
        val subjects = localDb.subjectDao().getModifiedSince(timestamp)
        val records = localDb.studyRecordDao().getModifiedSince(timestamp)
        // ... 其他表

        return buildMap {
            subjects.forEach { put("subject_${it.id}", it.toEntityData()) }
            records.forEach { put("record_${it.id}", it.toEntityData()) }
        }
    }

    private suspend fun getRemoteChangesSince(timestamp: Long): Map<String, EntityData> {
        // 从OneDrive AppFolder读取元数据文件
        val metadata = oneDriveApi.getFile("sisyphus/sync_metadata.json")
        val remoteVersions = parseMetadata(metadata)

        // 只下载版本号比本地新的实体
        return remoteVersions
            .filter { it.value > getLocalVersion(it.key) }
            .mapValues { oneDriveApi.getFile("sisyphus/entities/${it.key}.json") }
    }
}
```

### 9.3 冲突解决策略

```kotlin
class ConflictResolver {
    fun merge(entityId: String, local: EntityData, remote: EntityData): MergeResult {
        // 按字段合并
        val merged = mutableMapOf<String, Any?>()
        var hasConflict = false

        val allFields = (local.fields.keys + remote.fields.keys).distinct()

        for (field in allFields) {
            val localValue = local.fields[field]
            val remoteValue = remote.fields[field]
            val localTime = local.fieldTimestamps[field] ?: 0
            val remoteTime = remote.fieldTimestamps[field] ?: 0

            when {
                localValue == remoteValue -> {
                    merged[field] = localValue
                }
                localTime > remoteTime -> {
                    // 本地更新，用本地
                    merged[field] = localValue
                }
                remoteTime > localTime -> {
                    // 远程更新，用远程
                    merged[field] = remoteValue
                }
                else -> {
                    // 同时修改，标记冲突
                    merged[field] = localValue // 默认用本地
                    hasConflict = true
                }
            }
        }

        return MergeResult(
            mergedData = EntityData(merged),
            hasConflict = hasConflict,
            conflict = if (hasConflict) SyncConflict(entityId, local, remote) else null
        )
    }
}
```

## 十五、数据流水线

### 15.1 两次计算机制

数据处理采用两次计算机制，区分即时反馈和精细分析：

**即时计算**（番茄钟结束时自动触发）：
1. 番茄钟计时结束 → 自动生成 StudyRecord（基础数据：学科、时长、时间戳）
2. 立刻计算 XP（基于学科权重 + 时长）
3. 更新连续天数
4. 更新推荐队列

**精细计算**（用户补充详情时触发）：
1. 用户手动补充学习详情（备注、知识点等）
2. NLP 分析文本内容
3. 重新计算 XP（考虑学习类型、输入/输出分类）
4. 更新 FSRS 复习卡片状态
5. 更新输入/输出分类标签

### 15.2 NLP介入时机

NLP 引擎仅在用户手动输入文本时介入，不在番茄钟自动生成的数据上运行。这确保了：
- 番茄钟结束后的即时反馈不被网络延迟阻塞
- NLP 分析质量更高（基于用户主动提供的上下文）
- 离线场景下核心功能不受影响

```
番茄钟结束 → 即时计算 → 立刻反馈给用户
                    ↓
            用户补充详情（可选）
                    ↓
              NLP精细分析 → 重新计算 → 更新状态
```

```kotlin
// 通用加载状态
sealed class UiState<out T> {
    object Loading : UiState<Nothing>()
    data class Success<T>(val data: T) : UiState<T>()
    data class Error(val message: String, val exception: Throwable? = null) : UiState<Nothing>()
}

// ViewModel基类
abstract class BaseViewModel : ViewModel() {
    protected val _uiState = MutableStateFlow<UiState<*>>(UiState.Loading)
    val uiState: StateFlow<UiState<*>> = _uiState.asStateFlow()

    protected fun <T> launchDataLoad(
        block: suspend () -> T,
        onSuccess: (T) -> Unit = {},
        onError: (Throwable) -> Unit = {}
    ) {
        viewModelScope.launch {
            _uiState.value = UiState.Loading
            try {
                val result = block()
                _uiState.value = UiState.Success(result)
                onSuccess(result)
            } catch (e: Exception) {
                _uiState.value = UiState.Error(e.message ?: "Unknown error", e)
                onError(e)
            }
        }
    }
}
```

```kotlin
                    todayRecords = data.todayRecords,
                    isLoading = false
                )
                _recommendations.value = data.recommendations
            }
        )
    }

    fun startPomodoro(subjectId: Long, minutes: Int) {
        pomodoroManager.start(subjectId, minutes)
    }

    fun pausePomodoro() {
        pomodoroManager.pause()
    }
}

data class HomeState(
    val heroStats: HeroStats = HeroStats(),
    val todayRecords: List<StudyRecord> = emptyList(),
    val isLoading: Boolean = true,
    val error: String? = null
)

data class HeroStats(
    val totalXP: Float = 0f,
    val todayXP: Float = 0f,
    val level: Int = 1,
    val title: String = "初学者",
    val streakDays: Int = 0
)
```

## 二十、注意事项

### 20.1 代码规范

- ❌ 禁止 `!!` 非空断言，使用 `?.`、`?:` 或提前判空
- ❌ 禁止 `GlobalScope`，协程绑定生命周期
- ❌ 禁止硬编码像素值，使用 `dp`
- ❌ 禁止 `@Composable` 内直接执行网络/数据库操作
- ✅ 每个屏幕对应一个 `@Composable` + 一个 `ViewModel`
- ✅ 状态提升：Composable 只显示，ViewModel 提供数据
- ✅ 耗时操作用协程，`viewModelScope.launch` 调用

### 20.2 性能考虑

- 数据库查询使用 `Flow` 避免阻塞
- 列表使用 `LazyColumn` + `key` 参数
- 图片加载使用 Coil
- 避免在 Composition 中创建对象

### 20.3 安全考虑

- `release.jks` 加入 `.gitignore`
- API Key 使用 EncryptedSharedPreferences
- OneDrive token 定期刷新
- 用户数据本地加密存储

### 20.4 测试策略

- 单元测试：Domain层UseCase
- 集成测试：Repository + Room
- UI测试：Compose Testing
- 算法测试：FSRS/XP/推荐算法独立测试

## 二十一、算法理论参考

> 本章节为各算法的理论参数摘要，详细推导和论证见 `算法理论支撑.md`。

### 21.1 FSRS默认参数

- 目标保持率（requestRetention）：0.90
- SM-2过渡期初始EF：2.5
- 最大间隔：36500天（100年）
- 新用户前50张卡片使用SM-2过渡

### 21.2 XP曲线

| 等级区间 | 增长模式 | 说明 |
|----------|----------|------|
| 1-10级 | 低增速 | 新手保护期，避免挫败感 |
| 11-40级 | 线性增长 | 稳定提升阶段 |
| 41-70级 | 幂函数1.5 | 加速增长，奖励坚持 |
| 71-100级 | 放缓1.2 | 接近极限，每级需要更多努力 |

### 21.3 推荐算法

- 算法类型：贪心近似背包
- 推荐数量：3-5个任务/次
- 紧迫度公式：`urgency_factor = 1 / (1 + days / 7)`
- 时间预算是硬约束（背包容量）

### 21.4 输入输出比例

- 目标比例：输入30% / 输出70%
- 柔和提醒阈值：输入 > 50%
- 强烈提醒阈值：输入 > 70% 且持续3天以上
